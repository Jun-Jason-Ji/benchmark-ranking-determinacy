# 控制器参数敏感性扫描：协议（结果出来前冻结）

日期：2026-09-18。目的：回答“在合理范围内改变机械臂 PD 控制器参数或执行时延，两个公开 VLA 策略的成对排序会不会翻转”。这是 v3 方案 RQ0/RQ1 的第一个机器人侧探针，不是校准，不是真机证据，不是原始 SIMPLER 复现。

## 平台与已知偏离

- ManiSkill 3.0.1 + SAPIEN 3.0.3，Windows，CPU 物理 + GPU 渲染，`scripts/ms3_windows_compat.py` 把 Pinocchio IK 换成 ManiSkill 自带的 torch 雅可比求解器。历史真机标签来自 SIMPLER `main`（SAPIEN 2），二者不可直接对表。
- 策略：Octo 1.0 `octo-small`、`octo-base`（HuggingFace 权重），CPU JAX 0.4.20 推理，前后处理移植自 SIMPLER `octo_model.py`（widowx_bridge 设置）。旋转增量用 transforms3d 静态 xyz 欧拉角转轴角（原 SIMPLER main 约定）。
- 服务器与仿真分进程，本地 HTTP 通信。

## 因子与水平（`sweep_v1`）

| 条件 | 改动 | 说明 |
|---|---|---|
| nominal | 无 | ManiSkill Real2Sim 调好的刚度／阻尼／力矩上限 |
| stiff_x0.5 / stiff_x2.0 | 六关节刚度 ×0.5 / ×2 | 阻尼不变，等效欠阻尼／过阻尼变化 |
| damp_x0.5 / damp_x2.0 | 六关节阻尼 ×0.5 / ×2 | |
| force_x0.5 | 六关节力矩上限 ×0.5 | 饱和更早 |
| delay_1 | 执行策略 1 个控制步（200 ms）之前发出的动作 | 初始队列为“零位移、夹爪张开” |

改动通过进程内改写机器人类属性实现，建环境后从关节驱动属性回读核验（已在冒烟测试中确认）。

## 任务与集数

- 任务顺序：PutCarrotOnPlate（60 步）、PutSpoonOnTableCloth（60）、PutEggplantInBasket（120）、StackGreenCubeOnYellowCube（60）。
- 每个（策略，任务，条件）24 集，episode_id 0–23，覆盖该任务全部 12 个位置构型 × 2 个朝向构型各一次。
- 共同随机数：同一 episode_id 在所有条件、所有策略下用相同初始状态和相同策略随机种子（20260918 + episode_id）。
- 每集跑满最大步数，成功取最后一步的 `success`，与 SIMPLER ms3 评测脚本一致。

## 指标与判读规则（预先定义）

1. 每（策略，任务，条件）成功率及 Wilson 95% 区间。
2. 成对差值 Δ = rate(octo-small) − rate(octo-base)，按 episode_id 配对，配对自助法 95% 区间。
3. **点估计符号变化**：某任务上 Δ 在不同条件间符号相反。这是“候选翻转”。
4. **区间支持的翻转**：某任务上存在两个条件，一个条件的 Δ 自助区间整体 > 0，另一个整体 < 0。只有这种才在报告里称为“翻转”。24 集配对的功效有限，预期多数为不确定。
5. 策略内敏感性：各条件相对 nominal 的配对差值与区间，用来判断哪些参数方向根本不影响成功率。

## 停止／解释规则

- 若四个任务均无点估计符号变化，且策略内敏感性区间都跨零：结论是“在此范围内控制器参数不影响排序”，需要扩大参数范围或换参数族（物体摩擦、控制频率）再试。
- 若出现候选翻转但区间不支持：追加该任务该条件对的集数（继续 episode_id 24–47），不改条件。
- 若出现区间支持的翻转：保存该案例的首末帧、动作序列，作为图 1 候选；下一步做校准侧分析（这两个条件在 Bridge 示范轨迹上是否可区分）。

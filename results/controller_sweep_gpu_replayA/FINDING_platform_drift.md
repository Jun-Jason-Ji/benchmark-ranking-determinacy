# 发现：策略种子噪声与平台版本漂移的分解，以及一条被撤回的判定（2026-09-19 23:10，茄子 64 构型全普查）

生成的表格在同目录 `analysis_platform_drift.md`（`scripts/analyze_platform_drift.py`，会被刷新队列覆盖）；
本文件是人工结论，不被脚本改写。

## 1. 设计

三组数据此前既换了策略种子，也换了推理服务器版本（XLA 确定性开关、会话隔离先后引入），两者混淆：

| 集合 | 采集时间 | 服务器版本 | 种子基 |
|---|---|---|---|
| A | 2026-09-18 16:46 | 修复前 | 20260918 |
| B | 2026-09-18 23:05 | 修复后 | 20270101 |
| C | 2026-09-19 20:34 | 当前 | 20280101 |

补做 **A′**：在当前服务器上用 **A 的种子基** 重跑同样 64 个构型。于是

- **A vs A′** —— 同种子、不同版本 → **平台漂移**
- **A′ vs B vs C** —— 同版本、不同种子 → **策略种子噪声**

## 2. 平台漂移（同种子，换一代服务器）

| 策略 | 条件 | A | A′ | 差 | 逐集一致率 |
|---|---|---:|---:|---:|---:|
| octo-small | 标称 | 0.547 | 0.516 | −0.031 | 0.88 |
| octo-small | 力矩 ×0.5 | 0.484 | 0.469 | −0.016 | 0.80 |
| octo-base | 标称 | 0.297 | 0.375 | **+0.078** | **0.73** |
| octo-base | 力矩 ×0.5 | 0.297 | 0.344 | +0.047 | 0.80 |

平均绝对变化 0.043，最大 0.078；**逐集一致率只有 0.73–0.88**，即换一个推理栈版本就有 12–27% 的 episode 结果翻转。
早先的独立检查（`results/controller_sweep_gpu_det`，同种子、重启服务器、24 集）已给出同向结果：octo-base 6/24 → 9/24。

## 3. 策略种子噪声（同一代服务器，换种子）

| 集合 | 标称 small / base / Δ | 力矩 ×0.5 small / base / Δ |
|---|---|---|
| A′ | 0.516 / 0.375 / **+0.141** | 0.469 / 0.344 / +0.125 |
| B | 0.484 / 0.516 / **−0.031** | 0.500 / 0.391 / +0.109 |
| C | 0.453 / 0.500 / **−0.047** | 0.406 / 0.453 / −0.047 |

Δ(small−base) 标称：sd_seed = 0.104，单种子 95% 半宽 ±0.204，3 种子 ±0.118，10 种子 ±0.064；
要在 95% 下分辨其均值（+0.021）需要 **96 个种子**。

## 4. 结论一：一条判定被撤回

种子集 A 上的逐集自助给出 Δ(small−base) 标称 = **+0.250 [+0.08, +0.32]**，据此宣布 **octo-small 优于 octo-base**。
同一代平台的三个种子集给出 **+0.141 / −0.031 / −0.047**（均值 +0.021）——**该判定撤回**。

根因：对随机策略，"单个种子集 + 逐集自助"把"每个构型只抽了一个种子"当作总体，系统性低估不确定性。
官方 SIMPLER 协议平均 3 个种子正是为此（`--obj-episode-range 0 24` × `init_rng ∈ {0,2,4}`），
但后续文献普遍只跑一次。

## 5. 结论二：混代会把种子噪声虚高约一倍

用同一批 64 构型测 Δ 的跨种子标准差（`scripts/analyze_seed_noise.py`，对策略对与条件取中位）：

| 三个集合的来源 | sd_seed | 单种子 95% 半宽 |
|---|---:|---:|
| A（修复前）+ B + C —— **混代** | 0.093 | ±0.183 |
| A′ + B + C —— **同一代** | **0.055** | ±0.108 |

即此前观察到的"种子噪声"里约有一半其实是平台漂移。**结果目录必须记录服务器版本，跨版本的重复不得合并。**

## 6. 结论三：与公布数字的一致性

三个同代种子集的 octo-base 茄子基准值为 0.375 / 0.516 / 0.500，SIMPLER 公布值 **0.431** 正落在其中；
octo-small 为 0.453–0.516，公布值 0.569 偏高（公布值用 ms2 的 24 构型网格，此处为 ms3 的 64 构型，网格不同）。
换言之，**公布表里的三位小数本身带着约 ±0.07 的种子不确定性，从未被报告**。

## 7. 处理

1. "茄子标称 octo-small 优于 octo-base" —— **撤回**（路线页撤回节已记录）。
2. 分析脚本默认改用 A′（`analyze_benchmark_value.py` / `analyze_seed_noise.py`，旧集合需 `--legacy-a`）。
3. 并集界所依赖的四个不可见条件仍是种子集 A 的数据，队列 `queue_octo_union_conds.py` 正在当代平台重采
   （2 策略 × 4 条件 × 64 构型 × 2 种子）。
4. 论文增加一条方法学结论：**评测协议（种子数）与实现版本本身就是校准不可见的隐藏变量**，
   量级（Δ 上 0.19、单策略 0.078）与所研究的仿真参数模糊性（0.23）相当。形式化见 `docs/theory_protocol.md §6.1`。

## 8. 限制

- 仅茄子任务、仅 octo-small / octo-base 两个策略做了 A vs A′ 的漂移对比（@hist1 两个变体只有 A′ 一侧）。
- "服务器版本"是一个复合变量（jax/XLA 标志 + 会话隔离补丁 + 进程重启），未逐项拆分。
- 漂移方向在两个策略上不同号（small 略降、base 上升），样本量不足以判断是否系统性。

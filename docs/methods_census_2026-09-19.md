# 方法节草稿：把 SIMPLER 式基准当作有限构型总体来评测（2026-09-19）

本节整合 2026-09-19 的四条方法学更正，替代此前"逐集自助 + 多种子集"的默认口径。适用于任何以固定初始构型网格定义的
机器人评测基准（SIMPLER bridge/fractal 系列、ManiSkill 的 digital twin 任务等）。

## 1. 基准是一个有限的构型总体，而不是一个可无限抽样的分布

两个广泛使用的 SIMPLER 移植版都把 `episode_id` 映射到固定的初始状态：

```
pos  = (episode_id mod (n_xy · n_quat)) div n_quat
quat =  episode_id mod  n_quat
```

（ms3：`mani_skill/envs/tasks/digital_twins/bridge_dataset_eval/base_env.py:357`；
ms2：`ManiSkill2_real2sim/.../custom_scenes/put_on_in_scene.py:188`。物体缩放虽由 `np_random` 抽取，但资产表中每个物体
只有一个取值，不引入额外变化。）

| 任务 | 原版 SIMPLER (ms2) | ManiSkill3 移植 (ms3) |
|---|---:|---:|
| 茄子 | 8 × 3 = **24** | 8 × 8 = **64** |
| 勺子 / 胡萝卜 | 12 × 2 = **24** | 12 × 2 = **24** |
| 堆叠 | 24 × 1 = **24** | 24 × 1 = **24** |

三条直接后果：

1. **`episode_id ≥ 构型数` 是精确重复**，不是新样本。ms3 茄子的第 64–95 集与第 0–31 集是同一批场景。
2. **同一 `episode_id` 在两个移植版上不是同一个场景**（茄子尤甚：朝向数 3 vs 8，四元数数值也不同，最佳匹配点积仅 0.54）。
   跨栈的"逐集一致率"只在网格逐值相同的任务（勺子、胡萝卜）上有意义。
3. **一个场景的权重是 1/24 或 1/64**：在 24 构型的任务上，任何小于 0.042 的成绩差异不足一个场景。

### 1.1 官方协议本身就是普查

SIMPLER 原版 `scripts/octo_bridge.sh` 对每个 bridge 任务使用 `--obj-episode-range 0 24` 并在 `init_rng ∈ {0, 2, 4}`
上重复三次，即 **24 构型全普查 × 3 个固定策略种子 = 72 集**；公布表的分母正是 72（茄子 octo-base 31/72 = 0.431、
octo-small 41/72 = 0.569）。ms3 移植版的评测脚本 `real2sim_eval_maniskill3.py` 则默认 `num_episodes = 100`、
`episode_id = seed + i`，既未对齐网格也未做种子重复。**两者评测的不是同一个量**，其数字不可直接互比。

## 2. "重复"的含义取决于策略是否确定性

| 策略 | 采样来源 | 改变策略种子 | 合法的重复轴 |
|---|---|---|---|
| Octo（扩散动作头） | `jax.random.PRNGKey(seed)` 参与采样 | 产生新样本 | 构型 × 种子 |
| OpenVLA（贪心解码） | `do_sample=False`，seed 不参与 | **不产生任何新样本** | 仅构型（外加运行间数值噪声） |

实测：OpenVLA 在标称条件下两个"种子集"的 48 条记录逐条完全相同。因此对确定性策略，"多种子集复现"不是复现；
唯一的抽样轴是构型，而构型可以被穷举。

## 3. 估计目标决定区间，必须明写

| 估计目标 | 不确定性来源 | 估计量 |
|---|---|---|
| **(i) 基准值**：该基准自身的数字 | 构型抽样误差 = 0（全普查）；只剩策略噪声与运行间数值噪声 | Var(Δ̂) = N⁻² Σ_c [s²_A(c)/S_c + s²_B(c)/R_c] |
| **(ii) 泛化值**：同类场景上的表现 | 构型抽样 + 策略噪声 | 按构型聚类的配对自助 |

实现要点：

- **每构型只有一次运行时，(i) 退化为标准二项区间**——此时经验方差为零，若直接使用会得到零宽度区间。
  普查本身不收窄区间；**先把构型跑全（消除重复计数），再加运行次数（压策略噪声）**。
- **逐条相同的重复运行必须合并为一次观测**，否则方差凭空减半（OpenVLA 的两个"种子集"正是如此）。
- (ii) 的自助必须**按构型聚类**。实测在 64 构型任务上区间只宽约 4%、在 24 构型 × 4 重复上最多宽 1.33 倍，
  不改变本研究的任何判定结论，但有效样本量必须如实报告。

## 3b. 评测协议与平台版本本身就是校准不可见的隐藏变量

在构型全普查之上，仍有两个与仿真参数无关、却同样改变结论的变量，本研究把它们分离测量（茄子 64 构型，
`results/controller_sweep_gpu_replayA/FINDING_platform_drift.md`）：

| 变量 | 分离方法 | 量级 |
|---|---|---|
| **策略种子** | 同一代服务器、换种子基 | 单策略基准值 0.375 / 0.516 / 0.500；Δ 的 sd_seed = **0.055**（单种子 95% 半宽 ±0.108） |
| **平台版本** | 同种子、换一代推理服务器 | octo-base **+0.078**，逐集一致率仅 **73%**（octo-small −0.031 / 88%） |

两条实践结论：

1. **单种子集 + 逐集自助会给出站不住的判定。** 本研究的实例：种子集 A 上 Δ(small−base) = +0.250 [+0.08, +0.32]
   宣布 octo-small 更优，而同一代平台的三个种子集给出 +0.141 / −0.031 / −0.047。原因是该区间把"每个构型只抽了
   一个种子"当成了总体。官方 SIMPLER 协议平均 3 个种子正是为此，但后续文献普遍只跑一次。
2. **不要跨平台版本合并"种子集"。** 把修复前的数据计入时，测得的 sd_seed 从 0.055 虚高到 0.093——约一半的
   "种子噪声"其实是平台漂移。每个结果目录都应记录服务器版本（本项目记在 `run_meta.json` 的 `policy_server` 段）。

与本研究的主对象对照：茄子任务上力矩上限（校准精确不可见）带来的 Δ 位移按策略对为 **0.14–0.23**（四对均值 0.14，余量最大的 octo-small 对为 0.23），
而 3 个种子的评测半宽 ±0.062、10 个种子 ±0.034。**参数模糊性在任何现实评测预算下都不被噪声掩盖**，这是"更多评测无法解决该问题"的定量依据。

## 4. 判定阶梯（普查口径）

对每个策略对与每个条件，先按 (i) 或 (ii) 给出区间，再逐级判定：

1. **点校准**：只看标称条件的区间。这是当前文献的默认做法。
2. **并集界**：相容集合内的每个校准不可见条件都必须给出同号结论，区间取 [min 下界, max 上界]。
3. **GP 同时带**：在参数网格上建模并给出同时置信带，不外推、对全网格边缘化（赛道 S 的推荐配置）。

判据的形式是 |Δ̂| 与 **δ（参数引起的位移）+ h（评测半宽）** 的比较。本研究的量级：全普查 + 3 次运行下 h ≈ 0.07，
而茄子任务上力矩上限带来的 δ 按策略对为 0.14–0.23。**参数模糊性而非评测噪声是决定性误差来源**——这是把抽样误差压到零之后才能
干净说出的结论。

## 5. 报告规范（每个数字必须附带）

1. 覆盖了多少个构型 / 总构型数，是否完整普查；
2. 每构型的独立运行次数，以及这些运行是否真的独立（确定性策略需声明）；
3. 方差模型：经验方差 / 二项退化 / 单次运行未估计；
4. 估计目标是 (i) 基准值还是 (ii) 泛化值；
5. 所在移植版与版本（两个移植版的构型网格可能不同）。
